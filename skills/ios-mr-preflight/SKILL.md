# iOS MR 제출 전 점검

1. 사용자가 지정한 기준 브랜치와 비교 대상을 확인하세요. 지정하지 않았다면 확인 가능한 MR 정보에서 찾고, 기준이 불명확하면 브랜치를 추측하지 말고 질문하세요. 작업 트리의 미커밋 변경을 브랜치 diff에 조용히 섞지 마세요.
2. 브랜치 diff와 사용자가 제공한 이슈 설명을 읽으세요. 필요하면 변경에 직접 영향을 받는 코드만 확인하세요. 변경 이유가 확인되지 않으면 추측으로 채우지 마세요.
3. 저장소의 MR 템플릿을 우선 사용하세요. 적용할 템플릿이 없으면 [기본 PR/MR 템플릿](references/mr-template.md)을 사용하세요. 설명 초안을 작성할 때 [MR 작성 기준](references/mr-writing-guide.md)을 참고하세요.
4. 이번 변경에서 영향받는 경로만 수동 검증 항목으로 제안하세요. [수동 검증 항목 작성 기준](references/manual-verification.md)에 따라 재현 조건, 사용자 행동, 기대 결과와 검증 상태를 적으세요.
5. 한국어 Markdown으로 초안을 반환하세요. 확인한 기준 브랜치와 비교 대상을 표시하고, 작업 트리 변경을 포함했다면 그 사실을 밝혀주세요. MR 게시, 파일 수정, 빌드, 테스트 실행은 각각 명시적으로 요청된 경우에만 수행하세요.
